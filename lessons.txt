[answer]:

The “arrays” are tensors representing data flowing through the model.

1. Token IDs
------------

The tensor

    token_ids = torch.tensor([
        [10, 23, 7, 4],
        [10, 91, 7, 4],
    ])

can be written mathematically as

    X = \begin{bmatrix}
        10 & 23 & 7 & 4 \\
        10 & 91 & 7 & 4
    \end{bmatrix}

Its shape is

    X \in \mathbb{N}^{2 \times 4}

The first dimension means that we have 2 sequences. The second dimension
means that every sequence contains 4 token positions. Each integer is an ID
representing one token. The IDs are labels; they do not contain useful meaning
by themselves.

2. Embedding table
------------------

The tensor

    embedding_table = torch.randn(100, 8)

is a matrix

    E \in \mathbb{R}^{100 \times 8}

This means that the vocabulary contains 100 possible tokens and that every
token is represented by an 8-dimensional vector. For token ID 10, we select
row 10:

    E_{10} = \begin{bmatrix}
        e_{10,1} & e_{10,2} & \dots & e_{10,8}
    \end{bmatrix}

Therefore, the integer token ID 10 becomes the vector

    E_{10} \in \mathbb{R}^{8}

The values in this vector are learned during training.

3. Hidden states
----------------

When we write

    hidden_states = embedding_table[token_ids]

we perform the operation

    H_{b,s,:} = E_{X_{b,s}}

For every batch index b and sequence-position index s, we select the row of E
whose index is the token ID at X_{b,s}.

The output has shape

    H \in \mathbb{R}^{2 \times 4 \times 8}

because there are 2 sequences, 4 token positions per sequence, and each token
has become an 8-dimensional vector.

Conceptually, the operation is

    \begin{bmatrix}
        10 & 23 & 7 & 4 \\
        10 & 91 & 7 & 4
    \end{bmatrix}
    \quad\longrightarrow\quad
    \begin{bmatrix}
        E_{10} & E_{23} & E_7 & E_4 \\
        E_{10} & E_{91} & E_7 & E_4
    \end{bmatrix}

The purpose is to transform discrete language into continuous numerical
vectors that neural-network layers can process.

The general language-model flow is

    \text{text}
    \longrightarrow \text{token IDs}
    \longrightarrow \text{embedding vectors}
    \longrightarrow \text{Transformer layers}
    \longrightarrow \text{logits}

The embedding table starts with random values. During training, its values are
updated so that the vectors become useful for prediction. For example, related
tokens may eventually have smaller distances between their vectors:

    \lVert E_{\text{cat}} - E_{\text{dog}} \rVert
    <
    \lVert E_{\text{cat}} - E_{\text{airplane}} \rVert

Here, \lVert \cdot \rVert represents the distance between vectors.

LESSON 2 - TinyLanguageModel: Embeddings, Linear Projection, and Logits
==============================================================

Goal

Reference rule

Part 1: create a tiny language-model module
--------------------------------------------
Create this file:

    src/lesson02_logits.py

Put this code in it:

    import torch
    from torch import nn


    class TinyLanguageModel(nn.Module):
        def __init__(self, vocab_size, hidden_size):
            super().__init__()
            self.embedding = nn.Embedding(vocab_size, hidden_size)
            self.output = nn.Linear(hidden_size, vocab_size)

        def forward(self, token_ids):
            hidden_states = self.embedding(token_ids)
            logits = self.output(hidden_states)
            return logits


    def main():
        batch_size = 2
        seq_len = 4
        vocab_size = 100
        hidden_size = 8

        token_ids = torch.randint(
            low=0,
            high=vocab_size,
            size=(batch_size, seq_len),
            dtype=torch.long,
        )

        model = TinyLanguageModel(vocab_size, hidden_size)
        logits = model(token_ids)

        print("token_ids shape:", token_ids.shape)
        print("logits shape:", logits.shape)

        assert logits.shape == (batch_size, seq_len, vocab_size)


    if __name__ == "__main__":
        main()

Run it:

    python src/lesson02_logits.py

Expected output shape
---------------------

    token_ids: [2, 4]
    hidden_states: [2, 4, 8]
    logits: [2, 4, 100]

The linear layer applies the same mathematical transformation at every token
position:

    z = hW^T + b

where

    h \in \mathbb{R}^{8}
    W \in \mathbb{R}^{100 \times 8}
    b \in \mathbb{R}^{100}
    z \in \mathbb{R}^{100}

The 100 values in z are the logits: one unnormalized score for each possible
next token. A larger score means that the model currently prefers that token,
although logits are not probabilities yet.

Why nn.Module matters
---------------------
`nn.Module` gives PyTorch a place to register learnable parameters. Inspect
them by adding:

    for name, parameter in model.named_parameters():
        print(name, parameter.shape, parameter.requires_grad)

You should see parameters belonging to the embedding and linear layers. The
embedding and linear weights start with random values. Training changes them.

    from torch import nn


    class TinyLanguageModel(nn.Module):
        def __init__(self, vocab_size, hidden_size):
            super().__init__()
            self.embedding = nn.Embedding(vocab_size, hidden_size)

        assert targets.shape == (batch_size, seq_len)

        main()

Part 2: understand the shapes
------------------------------

The model produces:

    logits \in \mathbb{R}^{2 \times 4 \times 50}

The target tensor contains one correct token ID for every batch-position pair:

    targets \in \mathbb{N}^{2 \times 4}

`CrossEntropyLoss` expects the class dimension to be second, so the common
language-model pattern flattens the batch and sequence dimensions:

    logits.reshape(-1, 50) \in \mathbb{R}^{8 \times 50}
    targets.reshape(-1) \in \mathbb{N}^{8}

There are 8 predictions total: 2 sequences times 4 positions. Each prediction
has 50 possible classes.

Part 3: logits are not probabilities
-------------------------------------

At one position, suppose the model produces logits:

    z = [2.0, 1.0, 0.0]

These values are not probabilities. They can be negative, greater than 1, and
they do not sum to 1. Softmax converts them into probabilities:

    p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}

PyTorch's `CrossEntropyLoss` combines the required log-softmax operation and
negative log-likelihood calculation internally. Therefore, pass raw logits to
it. Do not call softmax before `CrossEntropyLoss`.

--------------------------------------
Add these lines after the first loss print:

expect it to always decrease dramatically after one step, but understand the

Inspect one gradient before `optimizer.step()`:

[question]: What is the meaning of logits, and why must logits have a final
dimension equal to vocab_size?

[answer]:

A logit is a raw score representing how suitable one possible token is as the
next token. Logits are not probabilities yet.

Suppose the vocabulary contains five tokens:

    ID 0: cat
    ID 1: dog
    ID 2: runs
    ID 3: sleeps
    ID 4: .

After processing a sequence, the model might produce:

    z = [1.2, -0.4, 3.8, 0.7, 2.1]

This vector contains five logits because there are five possible next tokens:

    z \in \mathbb{R}^{V}

where V is vocab_size. The scores are:

    cat     -> 1.2
    dog     -> -0.4
    runs    -> 3.8
    sleeps  -> 0.7
    .       -> 2.1

The largest score is 3.8, so the model currently prefers the token "runs".

The model needs one score per vocabulary item because the next token could be
any token in the vocabulary. For Lesson 2, the logits have shape:

    logits \in \mathbb{R}^{2 \times 4 \times 50}

This means 2 sequences, 4 positions per sequence, and 50 possible token
choices at every position.

The hidden size has a different purpose. A hidden state is an internal
representation of the context:

    h_{b,s,:} \in \mathbb{R}^{8}

It is not directly a list of possible words. The output layer converts the
hidden representation into vocabulary-sized scores:

    z = hW^T + b

where

    h \in \mathbb{R}^{8}
    W \in \mathbb{R}^{V \times 8}
    z \in \mathbb{R}^{V}

In PyTorch, this conversion is represented by:

    self.output = nn.Linear(hidden_size, vocab_size)

Therefore:

    hidden representation: [hidden_size]
    output logits:         [vocab_size]

During training, CrossEntropyLoss compares the logits with the correct token
ID. If the correct next token is ID 2, the loss uses the score at position 2
and encourages it to become larger than the scores for the other tokens.

DeepSeek-V3 follows this same general idea: its Transformer layers produce
hidden states, and the final projection converts each hidden state into
vocabulary-sized logits.

    import math
    import torch
    from torch import nn


    class CausalSelfAttention(nn.Module):
        def __init__(self, hidden_size):
            super().__init__()
            self.query = nn.Linear(hidden_size, hidden_size)
            self.key = nn.Linear(hidden_size, hidden_size)
            self.value = nn.Linear(hidden_size, hidden_size)

        def forward(self, hidden_states):
            query = self.query(hidden_states)
            key = self.key(hidden_states)
            value = self.value(hidden_states)

            scores = query @ key.transpose(-2, -1)
            scores = scores / math.sqrt(hidden_states.shape[-1])

            sequence_length = hidden_states.shape[-2]
            causal_mask = torch.triu(
                torch.ones(sequence_length, sequence_length, dtype=torch.bool),
                diagonal=1,
            )
            scores = scores.masked_fill(causal_mask, float("-inf"))

            weights = torch.softmax(scores, dim=-1)
            output = weights @ value
            return output


    def main():
        batch_size = 2
        sequence_length = 4
        hidden_size = 8
        hidden_states = torch.randn(batch_size, sequence_length, hidden_size)

        attention = CausalSelfAttention(hidden_size)
        output = attention(hidden_states)

        print("hidden_states shape:", hidden_states.shape)
        print("output shape:", output.shape)
        assert output.shape == hidden_states.shape


    if __name__ == "__main__":
        main()

Part 2: understand the equations
---------------------------------

For every hidden state h, three learned projections are created:

    Q = hW_Q
    K = hW_K
    V = hW_V

Q means query: what information is this position looking for?

K means key: what information does this position advertise that it contains?

V means value: what content should be copied if this position is attended to?

For sequence length S and hidden size D:

    Q, K, V \in \mathbb{R}^{S \times D}

The similarity between every query and every key is calculated by:

    scores = QK^T

Thus:

    Q \in \mathbb{R}^{S \times D}
    K^T \in \mathbb{R}^{D \times S}
    scores \in \mathbb{R}^{S \times S}

Each row says how strongly one position relates to every position in the
sequence. Division by \sqrt{D} keeps the dot products from becoming too large.

Softmax converts each score row into attention weights:

    A_{i,j} = softmax(scores_{i,:})_j

The output is a weighted mixture of value vectors:

    output = AV

Part 3: why the causal mask matters
------------------------------------

For next-token prediction, position i must not see future positions. With four
positions, the allowed pattern is:

    position 0: can see 0
    position 1: can see 0, 1
    position 2: can see 0, 1, 2
    position 3: can see 0, 1, 2, 3

The upper-triangular mask marks forbidden future positions. Replacing their
scores with negative infinity makes their softmax weights equal to zero.

5. What happens to a softmax row after one score is set to `-inf`?

LESSON 5 - Rotary Positional Embeddings: Giving Attention Order
==============================================================

Goal
----
Add positional information to attention with Rotary Positional Embeddings
(RoPE). Your causal attention layer currently compares hidden vectors, but
without positional information it does not know the difference between a
vector appearing first and the same vector appearing later. RoPE is the next
important building block on the path toward a DeepSeek-style Transformer.

Reference rule
--------------
Read the RoFormer paper's RoPE explanation and inspect how rotary embeddings
are used in the official DeepSeek-V3 implementation. Focus on the small
mathematical operation first; do not copy the complete production attention
implementation yet.

Part 1: create `src/lesson05_rope.py`
--------------------------------------
Implement these equations for a tensor `x` shaped `[batch, sequence, hidden]`.
The hidden size must be even because features are processed in pairs.

For each pair of features, define an inverse frequency:

    inverse_frequency = base ** (-pair_index / hidden_size)

For position `p`, calculate an angle:

    angle[p, pair_index] = p * inverse_frequency[pair_index]

Then rotate the feature pairs:

    RoPE(x, p) = x * cos(angle) + rotate_half(x) * sin(angle)

where:

    rotate_half([x0, x1]) = [-x1, x0]

The provided reference implementation should expose:

    rotary_embedding(x, position_ids=None, base=10000.0)

Run it with:

    python src/lesson05_rope.py

Part 2: understand the operation
---------------------------------

RoPE does not add a separate position vector to the hidden state. Instead, it
rotates each pair of features by an amount determined by the token position.
Position 0 has angle zero, so its rotation is the identity. Later positions
receive different rotations.

The rotation preserves the norm of each feature pair. This means positional
information is introduced without changing the magnitude of the vector.

In a Transformer attention layer, RoPE is applied to query and key tensors
before their dot product:

    query = rotary_embedding(query)
    key = rotary_embedding(key)
    scores = query @ key.transpose(-2, -1)

Values are not rotated. Queries and keys encode position-dependent matching;
values continue to carry the content that attention retrieves.

4. Why are queries and keys rotated, but not values?
